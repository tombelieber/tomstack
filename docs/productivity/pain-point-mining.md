# Pain Point Mining

## What it does

Turns real transcripts, support history, or session logs into clustered demand,
ranked pain points, product requirements, and E2E coverage gaps.

## When to reach for it

Use it when product decisions should be grounded in actual user behavior rather
than a brainstorm or an isolated anecdote.

## Common questions

- Is frequency enough to rank a pain point? No. Frequency and product value are
  kept separate before weighting.
- Can synthetic examples replace source history? No.
- Does it rewrite the PRD automatically? Only when that output is in scope.

## It's working if

Every major conclusion traces to source evidence, weighting is inspectable, and
the result ends in requirements or tests the team can act on.
